# 学术侦探 · 新手上手指南

> 本文档面向第一次接触项目的人。从下载代码开始，到第一次成功跑出调查结果。

---

## 第一步：从 GitHub 下载项目

打开 https://github.com/yadnuses/Academic-Detective ，你会看到项目的主页。有两种方式把代码拿到本地。

**方式一：克隆（推荐，后续能同步更新）**

打开终端（Mac 的"终端"应用，Windows 的 PowerShell），执行：

```bash
git clone https://github.com/yadnuses/Academic-Detective.git
cd Academic-Detective
```

这会创建一个叫 `Academic-Detective` 的文件夹，里面就是完整的项目。

**方式二：直接下载 ZIP**

如果你不习惯用命令行，在 GitHub 页面点击绿色的"Code"按钮，选择"Download ZIP"。解压后得到一个同名文件夹。

## 第二步：了解项目结构

下载完成后，项目目录长这样：

```
Academic-Detective/
├── run_investigation.py         ← 一键入口脚本
├── SKILL.md                     ← 完整调查方法论
├── config.yaml                  ← 当前使用的配置
├── DESCRIPTION.txt              ← 项目简介
├── archive/
│   └── flat_export_redundant_20260501/    ← 核心脚本目录
├── scripts/                     ← 工具索引、可视化和报告模板
├── data/                        ← 案例数据库（脱敏）
├── mentor-distill/              ← 导师蒸馏器（可选工具）
├── docs/                        ← 文档和演示
└── guides/                      ← 操作指南
```

核心脚本都放在 `archive/flat_export_redundant_20260501/` 下，文件名以 `模块名_工具名.py` 的方式命名。比如：

```
analysis_text_profiler.py       ← 文本分析
domestic_data_importer.py       ← 数据导入
domestic_data_validator.py      ← 数据验证
network_network_visualizer.py   ← 关系网络可视化
report_report_prompt_optimizer.py  ← 报告提示词优化
benchmark_engine.py             ← 学科基准线引擎
scholar_profile_matcher_v2.py   ← 模式匹配
```

文件名中的前缀（`analysis_`、`domestic_`、`network_`）对应的是 SKILL.md 中描述的抽象路径（`scripts/analysis/text_profiler.py` → 实际文件是 `archive/.../analysis_text_profiler.py`）。

## 第三步：安装依赖

项目依赖很少，纯核心功能只需要几个库：

```bash
pip install -r archive/flat_export_redundant_20260501/requirements.txt
```

如果还需要处理 PDF 文件（文本分析功能），安装 PDF 解析库：

```bash
pip install pdfplumber
# 或者
pip install PyMuPDF
```

如果不需要 PDF 分析（只跑数据验证和报告生成），可以不装 PDF 库。

注：你可以直接喂给AI让它帮你安装

## 第四步：两种使用方式

本项目支持两种截然不同的使用方式。请根据你的场景选择一种。

### 方式 A：作为 LLM Skill 使用（推荐，最常用）

这是项目的核心用法。你把项目喂给 AI（如 Claude、GPT、open claw，hermes），让 AI 按照 SKILL.md 中的七步框架执行调查。

**具体操作**：

1. 在 AI 对话工具中，上传或粘贴 `SKILL.md` 的内容。这是调查方法论的核心指令，包含完整的七步框架、工具清单、评分标准和证据规范。

2. 告诉 AI 你要调查的目标。例如：
   ```
   帮我用 academic-investigation skill 调查一下 XX大学的 XXX 教授。
   ```

3. AI 会按照 SKILL.md 中的流程，引导你一步步完成。你负责查询知网、下载 PDF、截图官网等人工操作，AI 负责分析数据、评分、比对异常、生成报告。

**核心原则**：
- AI 不做黑箱爬虫。知网、万方、Web of Science 这些付费数据库需要你人工搜索导出。
- AI 帮你分析你找到的数据，而不是替你去"找"数据。
- 最后生成的调查结论需要你用自己的判断力审核。

**配置文件的准备**：
项目根目录的 `config.yaml` 提醒你使用 `scripts/config.template.yaml` 作为模板：

```bash
cp scripts/config.template.yaml config.yaml
```

然后编辑 `config.yaml`，填入学者姓名、学校、已收集的数据文件路径等信息。

### 方式 B：作为本地工具链运行

如果你熟悉 Python 命令行，可以直接跑脚本。

**查看所有可用工具**：

```bash
python run_investigation.py --list-tools
```

**快速开始一个调查**：

```bash
python run_investigation.py --name "导师姓名" --school "学校名称"
```

这个命令会输出完整的七步调查框架，告诉你每一步该做什么、用什么脚本。

**跑文本分析**（需要先手动下载 PDF）：

```bash
python archive/flat_export_redundant_20260501/analysis_text_profiler.py \
  --input ./pdfs/论文1.pdf \
  --output ./data/论文1_profile.json
```

**跑六维质量评分**：

```bash
python archive/flat_export_redundant_20260501/analysis_paper_quality_rubric.py \
  --profile ./data/论文1_profile.json \
  --output ./data/论文1_quality.json
```

**数据验证**：

```bash
python archive/flat_export_redundant_20260501/domestic_data_validator.py \
  --input ./scholar_data.json
```

注意：所有脚本路径都以 `archive/flat_export_redundant_20260501/` 开头。`scripts/` 目录下的同名文件是兼容性 shim（小于 500 字节的桥接脚本），真实实现都在 `archive/` 下。

## 第五步：调查流程总览

一个完整的调查分为七个步骤。普通人不需要全部走完，根据需求选择深度。

| 步骤 | 内容 | 人工工作量 | 适合人群 |
|:---|:---|:---:|:---|
| Step 1 | 基本信息建立（官网、CV、教育背景） | 高 | 所有人 |
| Step 2 | 产出数量核实（知网搜论文数量比对） | 高 | 所有人 |
| Step 3 | 论文质量评估（六维评分） | 中 | 需深度报告的用户 |
| Step 4 | 关系网络分析（导师-学生、合作者） | 中 | 需深度报告的用户 |
| Step 5 | 异常检测与基准线比对 | 低 | 工具自动辅助 |
| Step 6 | 多源交叉验证 | 高 | 所有结论必须经过 |
| Step 7 | 报告生成 | 低 | AI 辅助生成 |

**快速筛查（15分钟）**：只做 Step 1 + Step 2，直接出结论。

**标准调查（1-2小时）**：Step 1 到 Step 4，配合评价数据库查询（研学网 7.5 万条评价）。

**深度调查（半天以上）**：完整七步 + PDF 文本分析 + 论文评分 + 模式比对 + 多源验证。

## 第六步：常见问题

**Q：我完全不懂编程，能用吗？**
能。推荐使用方式 A（把 SKILL.md 喂给 AI）。你只需要会打开 GitHub 下载 ZIP、会搜索知网、会保存网页截图。AI 会引导你每一步。

**Q：项目的核心优势是什么？**
不是技术，是方法论。SKILL.md 沉淀了三起经过验证的案例调查经验，包含完整的证据规范、评分标准和人机协作流程。大部分学术调查工具只是"搜一下"，这个系统能产出有结构、有依据、可溯源的深度报告。

**Q：案例数据库在哪里？**
`data/` 目录下存放脱敏后的案例数据库（46 条案例，含正常学者、已确认造假者、存疑案例）。这个数据库主要用于 Step 5 的模式比对（`scholar_profile_matcher_v2.py` 的 17 维特征匹配）。

**Q：我怎么贡献自己的调查案例？**
跑完引擎后加 `--contribute` 参数，会生成一个 JSON 文件。按照 CONTRIBUTING.md 中的步骤：Fork 仓库 → 上传到 `community_cases/pending/` → 创建 Pull Request。

**Q：报告是 PDF 格式的吗？**
项目原生输出的是 Markdown 格式的报告。如果需要 PDF，使用 `md_to_pdf.py` 进行转换（会自动生成雷达图、饼图等数据可视化图表）。

**Q：遇到问题去哪里问？**
提 GitHub Issue。项目有一个活跃的社区，社区贡献者在 Issues 中认领调查任务。

## 附录：快速命令速查

```bash
# 克隆项目
git clone https://github.com/yadnuses/Academic-Detective.git

# 安装依赖
pip install -r archive/flat_export_redundant_20260501/requirements.txt

# 复制配置模板
cp scripts/config.template.yaml config.yaml

# 查看所有工具
python run_investigation.py --list-tools

# 启动调查
python run_investigation.py --name "导师姓名" --school "学校名称"

# 文本分析
python archive/flat_export_redundant_20260501/analysis_text_profiler.py \
  --input ./pdfs/论文1.pdf --output ./data/论文1_profile.json

# 数据验证
python archive/flat_export_redundant_20260501/domestic_data_validator.py \
  --input ./scholar_data.json

# 模式比对
python archive/flat_export_redundant_20260501/scholar_profile_matcher_v2.py \
  --target ./scholar_data.json

# 生成报告提示词
python archive/flat_export_redundant_20260501/report_report_prompt_optimizer.py \
  --data ./scholar_data.json --template ./report_template.md --output ./report_prompt.md

# 转PDF
python scripts/md_to_pdf.py --input ./reports/调查报告.md --output ./reports/调查报告.pdf
```
